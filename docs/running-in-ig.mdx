# Running in Inspektor Gadget

Users can decide to run `micromize` gadgets using Inspektor Gadget directly. This guide explains how to build and run the `micromize` gadgets directly using the `ig` CLI or `kubectl gadget`. This is useful for development, testing, or running specific gadgets in isolation.

## Building Gadgets

You can build the gadgets using the provided `Makefile` or manually using the `ig` CLI.

### Using Make

To build all gadgets:

```bash
make build-gadgets
```

This will build the gadgets and export them as tarballs in `build/gadgets/`.
Note that `make` uses a versioned tag (based on `git describe`). You can check the tag used by running `make` or looking at the output.
To override the tag, you can run:

```bash
make build-gadgets IMAGE_TAG=latest
```

### Manually

To build a specific gadget (e.g., `cap-restrict`):

```bash
make cap-restrict
```

## Running with `ig` or `kubectl gadget`

Once built (or if you want to run from the registry), you can use `ig run` or `kubectl gadget run`.

### Running Locally Built Gadgets

If you built the gadget locally, you can run it by referencing the image tag you used.

```bash
sudo ig run ghcr.io/micromize-dev/micromize/cap-restrict:latest --verify-image=false
```

### Running from Registry

You can also run the gadgets directly from the container registry:

```bash
sudo ig run ghcr.io/micromize-dev/micromize/cap-restrict:latest
```

### Configuration Parameters

All gadgets support the following parameters:

- `enforce`: (boolean) If `true`, the gadget will block restricted actions. If `false`, it will only log them (audit mode).

#### Examples

**Run in Audit Mode (Log only):**

```bash
sudo ig run ghcr.io/micromize-dev/micromize/cap-restrict:latest --enforce=false
```

## Available Gadgets

- **cap-restrict**: Restricts privileged capabilities.
- **fs-restrict**: Restricts filesystem access.
- **ptrace-restrict**: Restricts `ptrace` usage.
